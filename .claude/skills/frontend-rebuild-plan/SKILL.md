# Перереалізація фронтенду: що вирішити до першої фічі

Цей скіл — про **порядок і рамки**. Деталі кожного шару — в окремих скілах (посилання нижче). Якщо рішення з розділу 2 ще не прийняте, не починай фічі, що від нього залежать: кожне з них у цьому репозиторії вже коштувало переписування.

## 1. Що переписувалось і чому (з `git log`)

| Що | Скільки разів / обсяг | Причина | Яке рішення запобігло б |
|---|---|---|---|
| i18n | `init multi-lang` + `add more translation` ≈ 3 850 рядків ретрофіту | тексти хардкодились у JSX і конфігах, константи з текстами на рівні модуля | i18n з першого компонента (рішення 1) |
| Auth-потік | 3 переробки (Redux → React Query → кілька акаунтів) | модель сесії не була визначена наперед | модель акаунтів і токенів до першого запиту (рішення 4) |
| Код-нотація | `change code notation convention` ×2 | правило жило в голові, а не в лінтері | стиль у ESLint з першого коміту (рішення 3) |
| Поля вводу (hint / error / розмір) | 4 коміти правок `Input` | не було контракту поля: коли показувати помилку, хто тримає місце під текст | контракт поля (рішення 9) |
| UI-кіт | `migration from xelar` ≈ 2 300 рядків, потім `brand book` | кіт перенесено з іншого проєкту з чужими токенами | токени до компонентів (рішення 2), процедура міграції в `frontend-ui-kit` |
| Випадні панелі | `improve dropdown panel` | списки обрізались модалками | портальні оверлеї до першого селекта (рішення 8) |
| Дозволи | 2 видалення дозволів | дозволи вигадувались під UI, а не з домену | доменна модель перед UI (рішення 6) |

Наслідки, що лишились у коді й досі: хаос відступів (12+ значень `gap`, px і rem упереміш), довільні `z-index` (1000 / 1100 / 60 / 50 / 20), посилання на неіснуючі шрифти (`--font-plus-jakarta`, `--font-lora`), `Button size` без стилів, опечатки `LoadingState.Ide` / `Pendding`, 7 файлів з прямим `import 'dayjs'`.

## 2. Рішення дня нуль

Кожне рішення фіксується в CLAUDE.md (розділ архітектури) **до** того, як з'явиться код, що від нього залежить.

1. **i18n з першого рядка.** Мови `uk` (дефолт) + `en` (ключі й fallback), без префікса в URL, мова з cookie → `Accept-Language`. Межа server / client через `server-only` / `client-only`. Типобезпечні ключі, `uk` типізована через `en`. Конфіги зберігають ключі, а не тексти. → `frontend-i18n`.
2. **Токени до першого компонента.** Кольори (зі шкалами 50–500), **шкала відступів**, радіуси, тіні, **шари z-index**, **тривалості анімацій**, типографіка лише зі шрифтів, які реально завантажені через `next/font`. → `frontend-styling`.
3. **Стиль коду — у лінтері, не в домовленостях.** Під конвенції CLAUDE.md:
   ```js
   // eslint.config.mjs (+ npm i -D @stylistic/eslint-plugin)
   {
     plugins: { '@stylistic': stylistic },
     rules: {
       '@stylistic/comma-dangle': ['error', { objects: 'always', arrays: 'always-multiline', imports: 'always-multiline', exports: 'always-multiline', functions: 'never' }],
       '@typescript-eslint/consistent-type-imports': 'error',
       'no-restricted-imports': ['error', { paths: [{ name: 'dayjs', message: 'Use @/lib/dayjs' }] }],
     },
   }
   ```
   `objects: 'always'` дає кому і в однорядкових `{ page, pageSize, }`. У поточному репозиторії це правило без масового виправлення не вмикай.
4. **Модель сесії.** Один чи кілька акаунтів, де живуть токени, як refresh працює між вкладками (`navigator.locks`), що завершує сесію (лише 401 / 403 на refresh, не мережа й не 5xx), що відбувається при перемиканні (повне перезавантаження). Обгортка API `{ status, data }` розгортається в інтерцепторі; помилка — `{ status: false, message: string | string[] }` → `getErrorMessage`. → `frontend-api-resource`.
5. **Серверний стан — лише TanStack Query.** Redux (або інший стор) — лише статус автентифікації. Профіль — query `Me`.
6. **Доменна модель і доступ — до UI.** Три механізми доступу (дозвіл, ієрархія ролей, участь у занятті) і їх відображення на клієнті вирішуються до першої захищеної сторінки. → `frontend-domain`.
7. **Стан, яким діляться, — у URL.** Дата / вид календаря, вкладки, режими, пошук, фільтри; ті самі імена параметрів, що й в API; `router.replace(..., { scroll: false })`; `Suspense` навколо `useSearchParams`.
8. **Оверлеї.** `Modal` / `SideModal` зі стеком (`useModalDismiss`), випадні панелі порталом у `body` з `position: fixed` (`useFloatingPanel`). Будуються **до** першого `Select`. → `frontend-modals`, `frontend-ui-kit`.
9. **Контракт поля форми.** Базовий компонент + `Form*`-обгортка; єдине правило, коли показується помилка (`useFormInputProps`); проп для щільних форм (`hideErrorMessage`); порожній селект = `''`. → `frontend-forms`.
10. **Розкладка папок і де живуть типи.** `interfaces/<domain>/` для всіх типів і пропсів, `configs/` для декларативних конфігів, `lib/services/` по класу на ресурс, хуки по файлу. Як у CLAUDE.md.
11. **Дати.** Обгортка `@/lib/dayjs` з локаллю мови й тижнем з понеділка; нативні `type="date" | "time"` не використовуються; локальний час для серій.
12. **Мінімальна перевірка якості.** `tsc --noEmit` + `eslint` на кожну зміну; unit-тести для чистих функцій `lib/` (`lesson-recurrence`, `calendar-grid`, `errors`, `jwt`), бо саме там найбільше крайових випадків.

## 3. Порядок побудови

| Етап | Що | Готово, коли |
|---|---|---|
| 0. Каркас | Next.js, TS strict, ESLint зі стилем, аліаси `@/`, `.env.example`, Dockerfile (`output: 'standalone'`, `NEXT_PUBLIC_*` на етапі build) | `npm run build` і `lint` чисті |
| 1. Основи | токени, reset, скролбар, шрифти, брейкпоінти + `mq()`; i18n (обидві мови, `common` / `ui` / `validation`); dayjs; `cn` | сторінка-заглушка перемикає мову, стилі лише на токенах |
| 2. UI-кіт | Button, Input / Textarea / PasswordInput, Select / MultiSelect (з `useFloatingPanel`), Checkbox / Switch, Modal / SideModal, Tabs, Table (+ `rowLock`, пагінація), Loading, headings; `Form*`-обгортки | кожен компонент має всі стани з матриці `frontend-ui-kit`, тексти з `ui` namespace |
| 3. Дані й auth | `apiClient` (обгортка, refresh, помилки), `query-client`, сервіс `auth`, `Me`, `usePermissions`, `RequireAuth`, `AuthModal` | логін / refresh / logout працюють, 401 на refresh завершує сесію |
| 4. Оболонка | `(public)` і `(platform)` групи маршрутів, сайдбар з `isVisible`, Header, сторінки-заглушки з перевіркою доступу | пункти навігації відповідають доступу різних ролей |
| 5. Довідники й користувачі | конфіг довідників, CRUD-модалки, `canManage` → `rowLock` | новий довідник додається одним записом конфігу |
| 6. Заняття | `LESSONS_VIEWS`, календар з URL-станом, фільтри, форма заняття, серії, групи, адмінка | правила створення з `domain.md` віддзеркалені в схемі |
| 7. Публічна частина | Welcome, `/schedule` без токена | працює анонімно |

Кожен етап закінчується оновленням CLAUDE.md (розділ «Поточний стан і пастки») і, якщо з'явилась повторювана процедура, — скілом.
